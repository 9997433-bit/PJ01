# SOTA 审计清单 — Survivor 类游戏（蛋壳特工队 / Survivor.io / Vampire Survivors）

> Round 1 审计产出 · 审计对象：割草生存（Survivor-like / Bullet Heaven）品类头部产品
> 目标：拆解 SOTA 标准，找出可超越的缺口，制定 Round 1~3 可量化验收标准。

---

## 一、蛋壳特工队（Survivor.io）核心玩法拆解

### 1.1 自动攻击（Auto-Attack）

- **零瞄准输入模型**：玩家只控制移动（单摇杆），所有武器自动索敌开火。输入带宽被刻意压缩到一维（走位），使"躲哪里"成为唯一决策，降低上手门槛同时保留深度。
- **索敌策略分层**：默认武器（如小刀）优先"朝向最近敌人"；投掷类（手雷/导弹）索敌"密度最高的敌群"；环绕类（护盾/无人机）无索敌，靠碰撞判定。不同索敌逻辑构成武器差异化的第一层。
- **攻击节奏参数**：每件武器由 `伤害 × 弹道数 × 攻速(冷却) × 穿透数 × 弹道速度 × 判定范围` 六维参数定义，升级即是对这些参数的离散跳变（如 Lv3 弹道 +1，Lv5 范围 +30%）。
- **进化（Evolution）机制**：武器满级 + 持有指定配件 → 合成进化武器（如 小刀+护腕→死亡射线）。这是构筑（build）系统的核心钩子，驱动玩家在三选一中做长线规划而非贪图短期收益。
- **手感反馈闭环**：命中 → 飘字 + 敌人受击闪白 + 击退 → 死亡爆浆 + 掉落宝石。每次命中必须有 ≥3 层反馈（视觉/位移/掉落）。

### 1.2 经验宝石（EXP Gems）

- **拾取即奖励的空间化经验**：敌人死亡掉落宝石，玩家必须**移动过去**拾取——把"获得经验"从被动数值变成主动走位风险决策（宝石常掉在敌群里）。
- **磁吸半径（Pickup Radius）**：基础磁吸范围小（约 1.5 个身位），可通过升级/道具扩大；"磁铁"道具全屏吸取制造爆发性升级快感（一次连升 2~3 级的多巴胺峰值）。
- **宝石分级与合并**：小怪掉蓝色（低经验）、精英掉紫/红（高经验）；地面宝石超过上限时旧宝石合并为高级宝石，防止性能崩溃同时保证经验不丢失。
- **经验曲线**：升级所需经验近似 `base × level^1.4~1.6` 递增；前 5 级刻意压低需求（30 秒内升 2~3 级），让玩家在第一分钟就体验两次三选一。

### 1.3 升级三选一（Level-Up Draft）

- **暂停式抉择**：升级瞬间游戏暂停弹出 3 选 1 面板——在高压割草中插入呼吸节拍，形成"紧张→决策→释放"的心流循环，平均每 40~60 秒一次。
- **选项池构成**：`新武器 / 已有武器升级 / 新配件（被动） / 已有配件升级`，武器槽与配件槽各限 6 个，槽满后只出已有项的升级——强制构筑收敛。
- **权重与保底**：已持有项出现权重更高（约 1.5~2 倍）；"幸运值"属性提升高稀有度选项概率；连续 N 次未出关键进化材料时有隐藏保底。
- **刷新与放弃**：提供有限次数的"刷新"和"放弃(换金币/回血)"按钮，给高级玩家操作空间。

### 1.4 波次递增（Wave Scaling）

- **时间轴驱动的刷怪脚本**：以 15 分钟（Survivor.io 章节制）为一局，刷怪由时间轴脚本控制：`t=0s 慢速触手怪`、`t=60s 快速小怪混入`、`t=180s 精英+围圈事件`……而非简单的数值线性放大。
- **三类压力事件**：① 常规流（持续从屏幕外沿刷入）；② 围圈事件（一圈敌人从四面收缩，考验找缺口）；③ 冲锋列队（一列高速直线冲过屏幕，考验垂直走位）。
- **数值缩放**：敌人血量随时间近似指数增长（每分钟 ×1.15~1.25），移速和密度阶梯式上调；玩家 DPS 靠进化武器跳变追赶——形成"压力累积→进化翻盘"的波浪型难度曲线。
- **精英怪（Elite）**：每 2~3 分钟刷一只高血量精英，掉落宝箱（宝箱=免费多重升级，是最强的间歇性奖励）。

### 1.5 Boss

- **定时登场**：章节中段（~7 分钟）小 Boss、结尾（15 分钟）大 Boss；登场有警告横幅 + 屏幕震动 + BGM 切换。
- **Boss 机制**：拥有专属弹幕/冲撞/召唤技能，带**红色危险区预警（telegraph）**——地面红圈/红条 0.8~1.2 秒后爆发，把"自动攻击游戏"在 Boss 阶段临时变成"弹幕躲避游戏"。
- **血条呈现**：屏幕顶部大血条 + 阶段分段（血量到阈值切换二阶段行为）。
- **击杀奖励**：大宝箱（3~5 连抽升级）+ 章节结算；Boss 存活期间常规刷怪减量，保证表演清晰可读。

### 1.6 单局循环总结

```
移动走位 → 自动攻击割草 → 拾取宝石 → 升级三选一 → 构筑成型/武器进化
    ↑                                                        ↓
 波次压力递增 ← 精英/围圈事件 ← Boss 战 ← 难度追赶构筑强度
```

局外循环（蛋壳特工队的商业化层）：装备抽取/合成、天赋树、章节推进——**本项目 Round 1~3 聚焦局内循环，局外系统仅保留轻量元进阶（如金币天赋）**。

## 二、蛋壳特工队 UI/UX 弱点（可改进点 ≥8 条）

1. **HUD 信息过载**：屏幕四角堆满局外系统入口（活动、礼包、体力），战斗界面被商业化元素侵占，局内沉浸感差。→ 我们局内 HUD 只保留战斗必需信息。
2. **三选一面板可读性差**：升级选项文字描述冗长（"攻击力提升10%"式流水账），缺少 before→after 数值对比和构筑关联提示（不告诉你这个配件是哪个进化的材料，新手全靠背表）。
3. **伤害飘字爆炸**：后期满屏白色数字互相重叠，既看不清单发伤害也遮挡敌人弹幕，纯视觉噪音。→ 需要伤害聚合（合并同源伤害为大数字）+ 暴击分色 + 上限剔除。
4. **血条/经验条位置割裂**：经验条在屏幕最顶端、血量在角色脚下、技能图标在底部——三条核心信息呈三角分布，高压战斗中视线来回跳。→ 应收拢到"角色周边 + 单一顶部条"两个注视区。
5. **磁吸与拾取无反馈层级**：宝石吸入没有音高递增、没有吸入轨迹差异，大量拾取时只是"哗"一声，浪费了最高频的奖励时刻。→ 连续拾取音高阶梯上升 + 轨迹拖尾。
6. **Boss 预警形式单一**：只有地面红圈，无屏幕边缘方向指示；Boss 从屏幕外接近时玩家完全无感知，常被屏外冲撞秒杀。→ 屏幕边缘方向箭头 + 距离脉冲。
7. **暂停/结算界面风格断裂**：局内是卡通渲染，弹窗却是通用扁平灰底面板，字体与配色和战斗场景完全脱节，像两个团队做的。→ 统一视觉语言（见 UI_STYLE_GUIDE.md）。
8. **升级瞬间打断过硬**：游戏瞬停 → 面板硬切弹出，无时间减缓过渡（slow-motion ease），割草的爽感被生硬掐断。→ 0.3s 时间膨胀渐入 + 面板弹性动画。
9. **无 build 总览**：局内看不到当前武器/配件的完整列表与等级（只有小图标一排，无 tooltip），玩家无法在三选一时回查自己的构筑。→ 三选一面板内嵌当前构筑栏 + 进化路线提示。
10. **移动端摇杆遮挡**：固定摇杆位于左下，但敌人常从左下刷入，拇指遮挡视野导致"看不见的死亡"。→ 动态摇杆（触点即原点）+ 摇杆半透明化。
11. **性能降级无策略**：后期敌人 300+ 时直接掉帧卡顿，没有粒子降级/尸体淡出等 LOD 策略，爽感巅峰期反而体验最差。
12. **色弱不友好**：经验宝石绿色 vs 毒圈绿色、危险红圈 vs 血包红色，色彩语义冲突且无形状冗余编码。→ 危险=红+条纹、奖励=青金+发光，双通道编码。

## 三、我们的超越目标

### 3.1 界面（Interface）— 5 条

| # | 目标 | 可验证标准 |
|---|------|-----------|
| I1 | **统一深色霓虹视觉语言**：局内 HUD、三选一、结算、暂停全部遵循同一套 token（见 UI_STYLE_GUIDE.md） | 所有 UI 颜色/圆角/字体取自 style guide 定义的 token，无游离硬编码色值 |
| I2 | **零遮挡 HUD**：战斗核心区（屏幕中央 60%）无任何常驻 UI；信息收拢为顶部单条 + 底部技能栏 | 截图检验：中央区域仅有飘字与实体 |
| I3 | **信息完备的三选一**：每个选项含 图标+名称+稀有度描边+before→after 数值+进化路线角标；面板内嵌当前构筑总览 | 面板可回答"我拿了什么、这个选项让我变强多少、离进化还差什么" |
| I4 | **方向感知系统**：屏外精英/Boss/宝箱有屏幕边缘方向指示器，按距离脉冲 | 精英刷新后 100% 出现指示器，进入屏幕后消失 |
| I5 | **响应式布局**：桌面（键鼠 WASD）与移动端（动态摇杆）双输入自适配，HUD 锚点随宽高比重排 | 375px~2560px 宽度下无元素重叠/溢出 |

### 3.2 手感（Game Feel / Juice）— 5 条

| # | 目标 | 可验证标准 |
|---|------|-----------|
| F1 | **命中反馈 ≥4 层**：受击闪白 + 击退 + 聚合飘字 + 命中粒子；击杀额外爆浆 + 掉落弹跳 | 逐层可开关调试，默认全开且 60fps 不掉 |
| F2 | **屏幕语言**：Boss 登场/大招/玩家受伤触发 screen shake（幅度分级）+ 受伤红晕 vignette + 击杀大量敌人时 0.1s hit-stop | 三种效果参数化（幅度/时长/衰减曲线）可调 |
| F3 | **拾取快感曲线**：宝石磁吸采用 ease-in 加速飞行，连续拾取 SFX 音高每 0.1s 阶梯 +1 semitone（封顶 12），升级瞬间全屏脉冲波 | 连拾 20 颗宝石可听出音高爬升 |
| F4 | **时间膨胀过渡**：升级触发 → 300ms 内 timescale 1→0 缓动，面板弹性入场（overshoot 1.06）；选择后 200ms 缓出回 1 | 无硬切暂停，过渡帧率稳定 |
| F5 | **走位手感**：角色移动加入 60ms 加速/80ms 减速缓动，朝向翻转有 squash-stretch；摇杆死区 ≤8%，输入延迟 ≤1 帧 | 键盘与摇杆盲测无"滑冰感/生涩感" |

### 3.3 深度（Depth）— 5 条

| # | 目标 | 可验证标准 |
|---|------|-----------|
| D1 | **武器×配件进化矩阵**：≥6 武器 ×≥6 配件，≥6 条进化配方，配方在三选一中渐进披露 | 每局可行成型 build ≥3 种，胜率路线不唯一 |
| D2 | **索敌逻辑差异化**：至少 4 种索敌（最近/最密/随机弹幕/环绕），武器间形成覆盖互补 | 单武器通关困难，混合构筑显著更强（数值可测） |
| D3 | **事件化刷怪脚本**：时间轴脚本含 常规流/围圈/冲锋列队/精英 4 类事件，支持配置化（JSON 定义波次） | 改 JSON 不改代码即可重排一局节奏 |
| D4 | **Boss 弹幕机制**：Boss ≥2 阶段、≥3 种带 telegraph 的技能（红区预警 0.8~1.2s） | 满血构筑下站桩必死，走位可无伤 |
| D5 | **风险回报设计**：宝石掉在敌群中 + 宝箱远离安全区 + "放弃升级换回血"选项，制造主动风险决策 | 回放数据中玩家移动热区覆盖 >70% 场地 |

## 四、Round 1~3 验收标准（可量化）

### Round 1 — 核心循环可玩（Vertical Slice）

**目标：一局完整可玩，核心循环闭合，性能达标。**

- [ ] 玩家移动：键盘 WASD + 触屏动态摇杆双输入，输入到位移延迟 ≤1 帧
- [ ] 自动攻击：≥2 种武器（最近索敌弹道 + 环绕型），命中/击杀反馈 ≥3 层
- [ ] 敌人系统：≥3 种敌人（慢速近战/快速近战/远程），从屏幕外沿刷入
- [ ] 经验宝石：掉落→磁吸→拾取→升级闭环，磁吸半径可成长
- [ ] 三选一：升级暂停弹出 3 选项（新武器/升级/被动），选项池权重正确
- [ ] 波次：时间轴脚本 ≥5 分钟内容，难度递增可感知（第 1 分钟 vs 第 4 分钟敌人密度 ≥3 倍）
- [ ] Boss：≥1 只，含登场警告 + ≥1 个 telegraph 技能 + 顶部血条
- [ ] 死亡/胜利结算界面（存活时间/击杀数/等级）
- [ ] HUD：血条、经验条、计时器、击杀数、武器栏，遵循 UI_STYLE_GUIDE
- [ ] **性能门槛：500 敌人同屏 60fps（见第五节基准方法）；首屏可交互 <2s**
- [ ] 无控制台报错，无内存持续增长（5 分钟局内堆增长 <20%）

### Round 2 — 深度与手感（Content & Juice）

**目标：构筑深度成型，手感全面拉满。**

- [ ] 武器 ≥6、配件 ≥6、进化配方 ≥4，三选一显示进化路线角标
- [ ] 索敌逻辑 ≥4 种；伤害飘字聚合 + 暴击分色
- [ ] 手感全量：screen shake（3 级幅度）、hit-stop、受伤 vignette、时间膨胀升级过渡、拾取音高阶梯
- [ ] 刷怪事件 ≥4 类（常规/围圈/冲锋/精英），JSON 配置化
- [ ] 精英怪 + 宝箱（多连抽升级）；屏外目标方向指示器
- [ ] 音频：BGM 分层（常规/高压/Boss）+ SFX ≥12 种
- [ ] Boss ≥2 只、各 ≥2 阶段；一局时长 10~15 分钟完整节奏
- [ ] 局内构筑总览面板（暂停与三选一内可查）
- [ ] **性能门槛：500 敌人 + 200 弹道 + 全特效 60fps；GC 卡顿单帧 ≤4ms**
- [ ] 数值验收：首局玩家平均存活 ≥4 分钟；成型 build ≥3 种可通关

### Round 3 — 打磨与元进阶（Polish & Meta）

**目标：完成度对标商业品，含轻量局外成长。**

- [ ] 局外元进阶：金币天赋树 ≥10 节点 / 角色选择 ≥2 名（属性差异化）
- [ ] 章节/难度选择 ≥2 档；数据持久化（localStorage/存档）
- [ ] 全 UI 动效打磨：面板弹性入出场、按钮 hover/press 态、结算逐条弹出计数动画
- [ ] 教学：首局无文字引导即可上手（新玩家盲测 5 人 ≥4 人 1 分钟内理解循环）
- [ ] 可访问性：屏幕震动/闪光开关、色弱双通道编码验证
- [ ] 平衡性通过：10 局模拟/实测，胜率 40%~70% 区间，无单一必选构筑（每武器选取率 >8%）
- [ ] 移动端实测：中端机（等效 4×降速 CPU throttle）≥45fps
- [ ] **性能门槛：800 敌人同屏 60fps（超越 Round 1 基准）；首屏 <2s 且 Lighthouse Performance ≥90**
- [ ] 零已知 P0/P1 缺陷；一局完整体验无软锁

## 五、性能基准（Performance Baseline)

### 5.1 硬指标

| 指标 | 基准 | 测量方法 |
|------|------|---------|
| **帧率** | **60 fps @ 500 敌人同屏**（Round 3 提升至 800） | 压测场景：脚本直接生成 500 活跃敌人 + 玩家全武器开火，录制 30s，P95 帧时长 ≤16.7ms |
| **首屏** | **可交互时间 <2s**（冷加载，Fast 4G 模拟） | 从导航开始到主菜单可点击；资源总量首包 ≤3MB（gzip） |
| 单帧预算 | 逻辑 ≤8ms / 渲染 ≤6ms / 余量 2.7ms | Performance 面板分帧剖析 |
| GC 卡顿 | 单次 GC 造成的帧超时 ≤4ms | 对象池覆盖敌人/弹道/粒子/飘字，稳态期零高频分配 |
| 内存 | 15 分钟一局堆增长 <20%，无泄漏 | 三局连打 heap snapshot 对比 |

### 5.2 必须采用的技术策略

- **对象池**：敌人、弹道、宝石、粒子、飘字全部池化，禁止战斗热路径 `new`。
- **空间分区**：碰撞检测用均匀网格（spatial hash），复杂度从 O(n²) 降到 O(n)；500 敌人碰撞 ≤2ms。
- **渲染批处理**：同图集精灵合批（单 drawcall 上限内），Canvas 方案用离屏缓存，WebGL 方案用 instancing。
- **实体上限与降级**：地面宝石 >150 时合并；粒子预算超限时按优先级丢弃；尸体 0.5s 淡出不留存。
- **帧率自适应**：连续 2s P95 >18ms 时自动降粒子档位（3 档），恢复后回升。

### 5.3 压测验收流程（每 Round 必跑）

1. `?stress=500` 调试参数进入压测场景（Round 3 用 `?stress=800`）。
2. 录制 30 秒 Performance profile，导出 P50/P95/P99 帧时长。
3. 断言：P95 ≤16.7ms，P99 ≤25ms，无 >50ms 长帧。
4. 首屏：Chrome DevTools Fast 4G + 4× CPU throttle，Lighthouse 跑 3 次取中位数，TTI <2s。
