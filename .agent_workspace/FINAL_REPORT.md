## 7. SOTA 对照结论

### 已实现超越（有证据）

1. **零遮挡 HUD + 单注视区收拢**（竞品弱点 #1/#4）— 移动端下半屏零常驻 UI；
2. **屏外方向指示器**（弱点 #6）— 竞品缺失项，我方落地含优先级与 HUD 避让；
3. **统一深色霓虹视觉语言**（弱点 #7）— DOM/CSS 全 token 化；
4. **动态半透明摇杆 + 多指防争用**（弱点 #10）— pointerId 绑定超出竞品；
5. **性能自适应降级链路**（弱点 #11）— 三档迟滞 + LOD，竞品后期直接掉帧；
6. **元素反应 × 融合武器矩阵** — 深度超过 Survivor.io 配方制（生效确认待 R3-1）；
7. **连击/Fever + Boss 处决 QTE** — 竞品不具备的主动技巧层。

### 未兑现的承诺（遗留）

1. 升级时间膨胀（弱点 #8）与拾取音高阶梯（弱点 #5）— 两轮未闭环；
2. 伤害飘字聚合（弱点 #3）— R3 在途；
3. 三选一 before→after 数值（弱点 #2）、色弱双通道（弱点 #12）；
4. 胜利条件 / 章节制 — 与「10~15 分钟完整节奏」的品类基本面冲突；
5. 局外元进阶（天赋/多角色/难度档）— R3 十条中整块未启动。

## 8. 工程复盘（多子代理协作）

### 有效实践

- **接口先行**：`ARCHITECTURE.md` 的 API 契约让 6 个并行子代理产物可合并；`WeaponSystem.snapshot()`、事件总线常量表、15 个音效挂点 id 都是「先立契约后并行」的收益；
- **装饰器接入**：ElementFusion 对 R1 代码零改动（装饰 dealDamage/buildPool），把跨分支冲突面压到最小；
- **测试基建复用**：Node VM 加载生产代码的模式从 33 项扩到 109 项，覆盖音频节流、QTE 生命周期、视口断言等原本「只能手测」的领域；
- **数据驱动**：`fusion-weapons.json` 权威调参 + 内嵌快照双轨，file:// 与 http 双环境兼容。

### 教训

- **「写好但没接」反复发生**：`snapshot()` 无调用方、融合系统无 script 标签、15 个音效挂点等电厂——契约先行必须配「接线验收」条款，否则每轮都在还接线债；
- **并行合并卫生**：探针文件残留冲突标记、PROGRESS.md 两轮未更新、报告路径偏离规范——多分支汇入需要一个专职「文档/产物对齐」步骤（本轮由 R3-6 承担）；
- **验收链路要与功能同轮交付**：性能优化做了但 D4/D6/D9 测量缺失，导致「优化真实、达标存疑」；
- **无头环境边界要提前声明**：真机帧率/Lighthouse/音频听感在本环境不可测，代理指标（SwiftShader FPS、逻辑帧成本、CSS 契约断言）应在标准制定时就写明替代关系（R2 验收表已做，值得保持）。
