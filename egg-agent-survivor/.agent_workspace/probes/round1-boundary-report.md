# Round 1 边界风险报告

## 范围与当前状态

测试创建期间核心模块由并发任务陆续落地，目前接入状态为：

- `tests/edge-cases.test.js` 通过 Node VM 直接加载浏览器版生产
  `js/utils/Vector2.js`；
- 仓库暂时没有 AABB 与经验结算模块，这两部分连接到
  `tests/helpers/game-logic-mocks.js` 中的最小契约；
- `tests/benchmark.html` 是零依赖 Canvas 2D 压力探针，不代表最终美术、
  AI、寻路和碰撞的完整帧成本；
- AABB/经验核心代码落地后应只替换测试文件顶部的 require，保留边界用例；
- 基准结果必须记录设备、浏览器、刷新率、窗口尺寸和 DPR，不能跨设备直接比较。

## 风险清单

| 优先级 | 边界/风险 | 可能表现 | 本轮探针 | 建议门槛与缓解 |
|---|---|---|---|---|
| P0 | 敌人数量无硬上限 | 刷怪叠加后主线程冻结、移动端浏览器被系统终止 | 基准固定覆盖 100/300/500 个移动、渐变、血条实体 | 配置 `maxActiveEnemies`；超限时延迟生成或替换最老/最远实体。上线门槛应由目标低端真机决定，不应直接把 500 当安全值 |
| P0 | 敌人死亡/换波内存泄漏 | 每局 Heap 单调增长，数分钟后卡顿或崩溃 | Chrome 的 JS Heap 只作现场提示；它不是自动泄漏判定 | 连续执行至少 20 次生成/清空周期，强制 GC 后 retained heap 应回到稳定平台；清理定时器、事件监听、粒子、音频节点和实体引用 |
| P0 | 重复游戏循环 | 重开后速度翻倍，CPU/GPU 持续升高 | 基准只创建一个 `requestAnimationFrame` 链 | 生命周期保存唯一 RAF id；退出局内场景时 cancel；禁止在 resume/restart 时并行创建循环 |
| P0 | 触摸坐标越界/失焦 | 角色卡死移动、滑出画布后持续攻击、刘海区域按钮不可点 | 基准使用 Pointer Events、pointer capture、clamp、`pointercancel` | 生产代码必须处理 `pointerup/cancel/lostpointercapture/visibilitychange`；坐标按 canvas DOMRect 与 DPR 转换；HUD 应应用 `env(safe-area-inset-*)` |
| P1 | 单帧刷怪尖峰 | 平均 FPS 正常但 1% Low 很低，出现明显停顿 | 自动采样记录 1% Low、P95 与 >50ms 卡顿帧 | 刷怪、寻路初始化和资源绑定分帧执行；对象池预热不得与战斗首帧重叠 |
| P1 | 每帧临时对象/闭包分配 | GC 周期性长帧，Heap 锯齿峰值扩大 | 基准的实体数组固定；场景切换时整体替换，便于观察回收 | 更新、碰撞和查询复用数组/向量；粒子与弹丸对象池设最大容量；不要让池只增不减 |
| P1 | Canvas 像素量失控 | 高 DPR 手机即使实体少也掉帧、显存上涨 | 基准将 DPR 限制为 2 并记录实际像素尺寸 | 渲染 DPR 建议可配置且动态降级；窗口 resize 后释放旧离屏画布；低性能模式关闭渐变、阴影和血条 |
| P1 | AABB 接触语义不一致 | 贴边时重复受伤、子弹穿边或无法拾取 | 单测同时覆盖“边缘算碰撞”和“必须有正面积重叠” | 战斗碰撞和触发器分别显式选择策略，不要依赖 `<`/`<=` 的偶然差异；负尺寸先标准化 |
| P1 | 大 `deltaTime` 穿透 | 切后台或掉帧后敌人跨过玩家/墙体 | 基准把单帧更新 clamp 到 50ms，并在后台取消采样 | 游戏恢复时重置时钟；物理使用固定步长与最多补帧次数；高速弹丸使用 swept collision |
| P1 | 经验阈值 off-by-one | 到达精确阈值不升级、连升吞经验、满级后数组越界 | 单测覆盖阈值前 1 点、精确阈值、跨多级与满级余量 | 经验总量使用非负安全整数；升级条件统一为 `>=`；满级明确保留、丢弃或转换溢出经验 |
| P1 | 空间分区退化 | 500 敌人时碰撞从近线性退化为 O(n²) | 当前渲染基准故意不含碰撞，避免混淆 GPU/逻辑成本 | 另建逻辑基准，分别测敌人-玩家 O(n) 与弹丸-敌人查询；使用网格/四叉树并监控每帧候选对数 |
| P2 | 多指输入争用 | 第二根手指覆盖移动 pointer，摇杆瞬移 | 当前探针仅演示单 active pointer | 记录移动/瞄准各自 pointerId；忽略未绑定 pointer；旋转与 resize 后重算控制区 |
| P2 | CSS 尺寸为 0 或极小 | 除零、实体被夹到负坐标、画布黑屏 | benchmark resize 最小钳制为 1 像素 | 初始化等待容器有非零尺寸；边界计算使用 `max(0, width - radius)`；折叠面板后暂停渲染 |
| P2 | 非有限数扩散 | 一个 NaN 位置污染碰撞树和整个渲染批次 | AABB mock 会拒绝 NaN/Infinity；生产 Vector2 的输入保护测试暂标为 TODO | 开发构建对位置、速度、伤害和经验加断言；生产构建在实体入口隔离并上报异常 |
| P2 | 低刷新率/高刷新率误判 | 60Hz 设备被误判为性能差，120Hz 结果无法比较 | 结果同时报告帧耗时和 FPS | 验收以 P95 帧耗时、1% Low 和卡顿帧为主；按显示刷新率归一化目标 |

## 建议验收矩阵

### 逻辑

运行：

```bash
node --test tests/edge-cases.test.js
```

核心接入后至少保持以下用例全绿：

1. 零向量 normalize 不产生 NaN；
2. 接近 `Number.MAX_VALUE` 的有限向量 normalize 后仍为单位向量；
3. AABB 分离、包含、贴边、零尺寸和负尺寸语义明确；
4. 经验值在阈值前、精确阈值、跨多级、满级和非法输入时行为确定。

### 渲染性能

运行：

```bash
./scripts/run-benchmark.sh
```

浏览器打开输出 URL 后点击“依次测试”，或访问
`tests/benchmark.html?autorun=1`。建议每种目标设备各跑三轮，取中位数。

临时建议门槛（需在真机数据后校准）：

- 100 敌人：P95 帧耗时不超过目标刷新周期，>50ms 帧为 0；
- 300 敌人：平均 FPS 不低于目标帧率的 90%，且 1% Low 不低于 30 FPS；
- 500 敌人：界面和输入仍响应，不出现持续长帧或 Heap 单调增长；
- 标签页切后台后，本轮采样必须作废，不能把浏览器节流数据写入结果。

## 后续核心集成检查点

1. AABB 与经验模块落地后替换对应 mock import；保留生产 `Vector2` 的 VM 加载；
2. 将“纯渲染”“AI 更新”“碰撞查询”“粒子/掉落物”拆成四个可切换场景；
3. 在敌人销毁、重新开局、场景卸载后记录实体池容量与事件监听数量；
4. 增加 Playwright 真机尺寸探针：320×568、390×844、768×1024，
   覆盖横竖屏切换、安全区和 pointer cancel；
5. 根据低端目标设备结果确定软上限、硬上限和动态降级档位。
